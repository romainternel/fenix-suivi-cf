# Audit Final — FENIX Stats CF — 2026-08-28

**Rôle :** Auditeur Final
**Méthode :** Exploration libre en navigateur réel (Playwright MCP), sans se limiter à une story ou une checklist connue — parcours principaux + chemins de traverse (états vides, mots de passe erronés, viewport mobile, retour navigateur)
**Contexte lu :** `CLAUDE.md` **absent du projet** (aucune trace, confirmé aussi par le Superviseur cette même session) — audit mené à partir de `docs/brief.md` (cible mobile 375–430px, joueurs 17–24 ans, usage < 2 min) et de ma connaissance directe du code acquise pendant cette session
**Données de test :** `ESSAI IA STAT.xlsm` (2 matchs, saison 2026-2027), serveur local (fichiers identiques à `master` au commit `4e08236`)

## 1. Résumé

**Presque prêt** : le cœur de l'app (import, dashboard, fiches joueurs, mode mobile, analyse) fonctionne bien et plusieurs bugs mobiles connus depuis juin sont en réalité déjà corrigés — mais un oubli de cache-busting datant de 8 versions et une erreur de saisie Excel non corrigée créent une vraie confusion utilisateur dès le premier contact.

## 2. Bugs trouvés

### 🔴 Bloquant
Aucun bug bloquant l'usage normal trouvé.

### 🟡 Gênant

**G1 — Deux joueurs affichés sous le même nom "Isaac MAURICE"**
- **Reproduction :** Joueurs → cliquer sur l'un ou l'autre des deux ronds "IM" du terrain (visuellement identiques, côte à côte)
- **Constat :** `selectJoueur('Isaac.M')` et `selectJoueur('Julien.L')` affichent tous les deux "Isaac MAURICE / AG" en en-tête de fiche. Les stats affichées sont bien celles du bon joueur (rattachées par prénom depuis DATA), seul le nom complet affiché est faux pour Julien — cause : ligne "Julien.L" de la feuille Excel "Joueurs" avec `NOM ID = "Isaac MAURICE"` (déjà signalée au coach en cours de session, toujours présente dans le fichier actuel). Le même doublon apparaît aussi dans le sélecteur "Vue joueur" et dans le Dashboard.
- **Impact :** un coach ou un joueur ne peut pas savoir avec certitude qui est qui entre les deux ronds "IM".
- **Fix :** à corriger dans le fichier Excel (pas un bug de code) — le coach en a déjà été informé.

**G2 — Page "Analyse" sans donnée importée : cartes à zéro au lieu d'un message clair**
- **Reproduction :** Ouvrir l'app fraîchement (ou onglet Analyse avant tout import) → onglet Analyse
- **Constat :** Le Dashboard affiche correctement "IMPORTER LES DONNÉES" quand rien n'est chargé. La page Analyse, elle, affiche directement les cartes terrain/FENIX/ADVERSAIRE avec `POSS 0 · BUT 0/0 · EFF% 0%` partout, sans indiquer qu'aucune donnée n'est chargée — un premier visiteur peut croire à un bug plutôt qu'à une simple absence d'import.
- **Fix suggéré :** réutiliser le même message d'état vide que le Dashboard tant que `DATA.length === 0`.

**G3 — "Vue joueur" (aperçu staff) : page blanche silencieuse si aucune donnée n'est importée**
- **Reproduction :** Sans importer de fichier → bouton "👤 Vue joueur" → sélectionner n'importe quel nom dans la liste (qui, en plus, propose une liste de joueurs de l'an dernier codée en dur — voir G4) → "Voir sa vue →"
- **Constat :** L'en-tête du mode joueur s'affiche (nom, onglets Ma Fiche/Stats Match/Impact) mais tout le corps de la page reste **entièrement blanc**, sans aucun message. Aucune erreur JS en console — c'est un échec silencieux, pas un crash.
- **Fix suggéré :** afficher un message ("Aucune donnée importée") dans `renderPlayerFiche()` quand `DATA` est vide.

### 🟢 Amélioration suggérée

**G4 — Liste de joueurs "fantôme" dans "Vue joueur" avant tout import**
- **Constat :** Sans aucune donnée chargée, le sélecteur "Vue joueur" propose déjà 21 noms (Gabriel, Simon, PP, Jules F, Zach…) — un roster de saison précédente codé en dur dans `player-mode.js`, qui n'a rien à voir avec l'équipe actuelle. Lié à un point déjà identifié en cours de session : `JOUEURS_TERRAIN` n'a pas de valeur par défaut vide.
- **Suggestion :** initialiser `JOUEURS_TERRAIN` à un tableau vide par défaut plutôt qu'à un roster figé — combiné à G3, ça évite de proposer un menu qui ne mène nulle part.

**G5 — Position codes ("ARG", "ARD"…) mélangés aux noms de joueurs**
- **Constat :** Dashboard et filtre "Notes" listent "ARG" et "ARD" comme s'il s'agissait de joueurs (0 tir, 0%, pas de temps de jeu). Vient de lignes DATA où la colonne "Joueurs" contient un code de poste au lieu d'un nom — probablement une saisie liée à des actions adverses non attribuées.
- **Suggestion :** pas un bug de l'appli à proprement parler (donnée source), mais l'appli pourrait filtrer les valeurs qui ressemblent à un code poste (2-3 lettres majuscules connues : GB/AG/AD/ARG/ARD/DC/PIV) plutôt que de les afficher comme un joueur.

**G6 — Retour navigateur (back) sort de l'application**
- **Constat :** L'appli est un SPA à onglets sans historique d'URL — le bouton "précédent" du navigateur ne revient pas à l'écran précédent dans l'app, il quitte carrément la page. Sur mobile, le geste de swipe-retour est un réflexe très courant chez la cible 17-24 ans.
- **Suggestion :** non structurant à corriger maintenant, mais à garder en tête si des retours utilisateurs mentionnent une perte de contexte inattendue.

**G7 — "Top points à corriger" un peu serré sur les libellés longs (mobile 375px)**
- **Constat :** Sur "Hs/Répart/Changmt", le chiffre colle presque au libellé (DOM correct — `justify-content:space-between` — mais peu de marge visuelle restante à 375px).
- **Suggestion :** cosmétique uniquement, pas gênant pour la lecture.

**G8 — Mot de passe vide accepté comme tentative "normale"**
- **Constat :** Cliquer sur "ACCÉDER" sans rien saisir affiche "Mot de passe incorrect" comme n'importe quelle mauvaise tentative — fonctionnel mais un peu abrupt pour un champ resté vide.
- **Suggestion :** mineur, pas prioritaire.

## 3. Bonnes surprises — bugs connus, retestés, non reproduits

- **S-04 (QA-02, juin) — canvas "face" non pleine largeur sur mobile** : retesté à 375px sur l'onglet Impact du mode joueur → **corrigé**. "CENTRAL" s'affiche bien en pleine largeur en premier, "EXT GAUCHE"/"EXT DROIT" côte à côte en dessous, conforme au critère d'origine.
- **S-03 (QA-02, juin) — header sticky masqué sous la barre sur iPhone** : retesté à 375px sur les onglets Ma Fiche et Stats Match → aucun chevauchement constaté.
- Aucune de ces corrections n'a de rapport QA associé — à confirmer formellement si l'occasion se présente (voir compte-rendu Superviseur de cette session).

## 4. Ce que je n'ai pas pu tester

- **Export PDF / PowerPoint de la fiche joueur** : le bouton PDF appelle `window.print()`, qui ouvre une boîte de dialogue native bloquant complètement le pilotage automatisé (déjà documenté dans `docs/regression/audit-complet-2026-08-26.md` — gel du navigateur Playwright observé lors de cet audit précédent). Non re-tenté ici pour éviter de reproduire l'incident.
- **Comportement multi-onglets / multi-appareils simultanés** (ex. un joueur connecté pendant que le staff réimporte un fichier) — hors de portée d'un test à un seul navigateur.
- **Vrai appareil mobile tactile** (le viewport 375×667 simule la taille mais pas les gestes tactiles réels, le clavier virtuel, ni les navigateurs mobiles spécifiques Safari iOS / Chrome Android).
- **Volume réel de données** (saison complète avec 15-20 matchs) — testé uniquement avec 2 matchs, certains seuils (badges "signature", régression saison) ne se déclenchent qu'au-delà de 3-5 matchs et n'ont donc pas pu être vus en conditions réelles de fin de saison.

## 5. Verdict

**PRESQUE PRÊT**

Aucun bloquant. Avant une mise en avant plus large auprès des joueurs, je recommande de traiter dans l'ordre :
1. G1 (corriger la ligne Excel "Julien.L") — 2 minutes, déjà signalé au coach
2. G2 + G3 (états vides sans donnée) — petits correctifs, évitent une mauvaise première impression si quelqu'un ouvre l'app avant l'import
3. Le reste (G4-G8) peut attendre — aucun n'empêche un usage normal
